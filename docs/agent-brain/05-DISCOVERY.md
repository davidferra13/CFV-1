# Discovery Stage Rules

> How to gather information without interrogating. The goal: learn everything needed to build a menu and quote, in as few exchanges as possible.

---

## The 4 Universal Questions

Every inquiry, regardless of scenario, needs these resolved before a menu can be drafted:

1. **Date** - When is the dinner?
2. **Guest count** - How many people? (estimate OK)
3. **Dietary/allergies** - Anything the chef needs to plan around?
4. **Menu direction** - What kind of food? (cuisine, vibe, favorites, cravings)

## Conditional Questions (Ask Only When Unknown)

| Question                               | Ask when...                              | Skip when...                           |
| -------------------------------------- | ---------------------------------------- | -------------------------------------- |
| Location/address                       | New client OR new venue                  | Repeat client, same location           |
| What chef brings                       | New client, never worked together        | Any repeat client                      |
| How pricing works                      | New client                               | Repeat client (they know)              |
| Occasion/special event                 | Not volunteered in initial message       | Already mentioned                      |
| Service style (plated, family, buffet) | Large group (12+) or client seems unsure | Standard dinner (2-10)                 |
| Beverage involvement                   | Client mentions drinks/pairings          | Default: chef doesn't handle beverages |

## Gathering Strategy

### For new clients:

- Ask all 4 universal questions in the first response
- Include "what I handle" context naturally (not as a list, as a sentence)
- Let them know pricing depends on the menu, but give the structure

### For repeat clients:

- Ask only what CHANGED: "Same setup or different this time?"
- Reference last event naturally: "Want to do something similar to last time or switch it up?"
- Never re-explain your process to someone who's lived it

### For referrals:

- Acknowledge the connection: reference who sent them
- Still ask all 4 universals (you don't know THIS person's group)
- Don't assume they want what their friend had

## Anti-Patterns (Never Do These)

- Don't ask for the exact address in the first message (too invasive, too early)
- Don't ask for a full guest list with names (just count for now)
- Don't ask about budget directly (let the quote handle it)
- Don't send a questionnaire or form (feels clinical)
- Don't ask one question per message (consolidate)
- Don't ask questions you can answer yourself from the inquiry data
- Don't repeat information back as a question ("You said 8 guests, is that right?")

## Data Capture Priority

After the first exchange, the system should have:

- Contact name (usually from the message itself)
- Approximate date
- Approximate guest count
- At least one dietary signal (even "no restrictions")
- Some menu direction signal

After the second exchange:

- Exact date confirmed
- Exact count (or range: "6-8")
- Full dietary picture
- Enough to draft a menu proposal
