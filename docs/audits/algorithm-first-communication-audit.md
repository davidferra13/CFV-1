# Algorithm-First Communication Audit

Date: 2026-05-17

Scope: lib/communication, lib/ai, lib/ai/dispatch, and lib/cil. I classified files by reading imports, exports, model call sites, catch paths, fallback branches, and selected implementation bodies.

Classification definitions:

- ALGORITHM: deterministic rules, formulas, DB access, types, constants, or templates. No model needed.
- AI-ENHANCED: AI may improve output, but the file has a formula, template, heuristic, keyword, null, or graceful fallback.
- AI-REQUIRED: a user-facing workflow or business result depends on model output and fails, throws, or returns no useful result without AI.
- AI-ONLY: AI runtime, provider, queue, adapter, prompt, persona, or Remy-only surface where non-AI operation is not expected.

## Priority remediation order

1. Central parser guardrails: keep lib/ai/parse-ollama.ts strict, but require every business caller to decide between formula fallback, manual review, or explicit unavailable UI.
2. Import and extraction fallbacks: fix inquiry, receipt, recipe, document, transcript, and brain-dump flows before polishing generated copy. These create records and affect safety data.
3. Command execution safety: expand deterministic command-intent patterns and make command-orchestrator execute only structured tasks when AI is offline.
4. Communication draft skeletons: add template fallbacks for follow-up, quote, review, social, campaign, and bio drafts so the chef can still edit from a starting point.
5. Timeline generators: consolidate callers on formula-backed prep-timeline-actions, then add the same deterministic run-of-show pattern to service-timeline.
6. CIL social drafts: add a static social draft shell so signal dispatch can still create an approval item when AI is down.
7. AI-only surfaces: keep provider, queue, browser, and Remy-only files gated behind health checks and clear unavailable states. Do not force fake deterministic behavior into pure AI surfaces.

## Recommendations

- Treat parseWithOllama as an unreliable enhancement boundary, not as the first line of business logic. Callers should own fallback behavior.
- Prefer formulas for pricing, allergens, tax categorization, sentiment, prep scheduling, and business metrics. The repo already has good examples in with-ai-fallback.ts, prep-timeline-actions.ts, allergen-risk.ts, pricing-intelligence.ts, and business-insights.ts.
- For record creation imports, save low-confidence fallback records only as drafts or review items. Never silently commit guessed allergy, date, or payment fields.
- For generated communication, use approved template skeletons as the deterministic floor. AI can personalize, but sending must remain approval-first.
- Add offline tests around every AI-REQUIRED file in the critical table. Test that the user sees either a useful fallback draft or an explicit manual review path.
- Add source metadata such as formula, heuristic, template, ai, or unavailable to results that currently hide their degradation mode.
