## Source Research

This index continues the research-to-build extraction from the human-body, memory, transparency, support-network, and organized-human transcript. The research is conceptual, not direct customer evidence, so these builds should be treated as product theses that need focused verification after implementation.

The Circles extraction additionally uses implementation evidence from `docs/agent-contexts/circles-domain.md` and `docs/architecture/circles-current-state-inventory.md`.

## Master Product Thesis

ChefFlow should work like a chef's external nervous system: it captures signals passively, labels what is known and unknown, tracks what is active or waiting, preserves relationship memory, and lets the chef stop and resume work without reassembling context.

| -------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |

## Recommended Sequence

1. Build `circles-operating-loop-build-extraction.md` first if the next build touches shared relationships, Dinner Circles, Crew Circles, guests, staff, vendors, partners, or community.
2. Build `truth-net-evidence-labels.md` first if the next build touches AI, inferred signals, or confidence.
3. Build `passive-capture-triage-dock.md` first if the priority is daily operator relief.
4. Build `waiting-state-radar.md` after or alongside the operating-loop adapter work.
5. Build `clean-stop-resume-trails.md` once activity/resume sources are confirmed.
6. Build `support-network-map.md` after client profile and relationship surfaces are stable enough to avoid creating a second client model.
