# Every Scenario Where a Client Still Leaves ChefFlow

> **Purpose:** Map every moment a client, consumer, host, or guest exits ChefFlow to use another tool.
> These are the boundaries of the client-side product. Some exits are permanent because ChefFlow will
> never replace Google, Instagram, maps, banks, family group chats, or venue/vendor systems. Others are
> opportunities to reduce friction or make the round-trip back into ChefFlow smoother.
>
> **Companion docs:**
>
> - `docs/research/client-never-leaves-analysis.md` (240 workflows that stay in-app)
> - `docs/research/chef-exit-points-analysis.md` (chef-side exit scenarios)
> - `docs/research/chef-never-leaves-analysis.md` (chef-side in-app workflows)

## THE PATTERN: Three Types of Client Exits

### 1. PERMANENT EXITS (ChefFlow should never try to replace these)

External platforms with their own ecosystems. ChefFlow's job: reduce friction at the boundary.

- Open web/search/social discovery (1-6, 60-61, 85)
- Third-party reputation surfaces (8, 12, 87)
- Native communication channels (27-29)
- Banks, cards, chargebacks, and informal payment apps (35-36, 40)
- Venue/vendor ecosystems (43, 45-47, 51, 73-74)
- Travel/maps/rideshare/hotels (76-79)
- Legal, medical, procurement, and regulated review (62, 81-83)
- Personal photo libraries and social memory systems (86)

**Strategy:** Clean link-outs, clear return paths, exported packets, and "bring it back" capture.

### 2. REDUCIBLE EXITS (ChefFlow could eliminate or reduce these)

Client leaves because ChefFlow does not yet provide enough confidence, structure, or self-service.

- Service-area confidence and public chef proof (7, 11, 13)
- Quote comparison, favorites, split cost math (15, 19-20)
- Event deadlines and add-to-calendar (23-24)
- Email replies and support recovery (30, 34)
- Guest names, dietary forms, and guest changes (52, 54, 58)
- Household preferences and menu revision requests (66-67)
- Home access, kitchen photos, equipment confirmation (68, 71-72)
- Account/privacy self-service (84)
- Shared recipes and event memory archive (90-91)

**Strategy:** Make the client portal the obvious place for decisions, confirmations, and memory.

### 3. BRIDGEABLE EXITS (Client will still go external, but ChefFlow can smooth the round-trip)

- Friend recommendations -> referral links and share cards (2)
- Marketplace comparison -> saved shortlist and quote compare (5, 14, 17)
- Shared decision-making -> cohost links and proposal sharing (18, 22, 31)
- Venue and planner systems -> event packet export/import (25-26, 44, 69-70)
- Files and inspiration -> upload/link pinning (32, 60)
- Informal payments and reimbursements -> receipt/export/offline logging (36, 38-39, 41-42)
- Invitation platforms -> guest import and dietary links (48, 53, 56, 59)
- Nutrition, wine, weather -> summary panels plus external links (63-65, 75)
- Day-of movement -> live status and arrival windows (80)
- Corporate approvals -> proposal packet export (82)
- Post-event sharing -> share-ready recap, referral links, review links (85, 88-89)

**Strategy:** Do not pretend ChefFlow is the whole internet. Make every external trip preserve context.

## PRIORITY RANKING (By Client Pain)

**Leaves most often for:**

1. Texting or calling the chef
2. Checking personal/family calendar
3. Sharing event details with spouse, assistant, guests, or planner
4. Guest RSVP and dietary collection
5. Payment app or bank checks
6. Instagram/Pinterest menu inspiration
7. Google/Yelp review validation
8. Venue, parking, weather, and map checks
9. Invitation platform coordination
10. Receipt download/reimbursement
11. Post-event photo sharing
12. Public review posting
13. Quote comparison across chefs
14. Alcohol, rental, floral, and non-food vendor coordination
15. Recalling what was served months later

**Highest-impact improvements:**

1. **Client message consolidation** = reduces texting/email confusion
2. **Guest RSVP + dietary autopilot** = reduces host chasing and spreadsheets
3. **Calendar sync + deadline feed** = reduces missed payment/menu/guest count deadlines
4. **Shareable cohost/planner packet** = bridges shared decision-making
5. **Quote compare + favorites** = keeps shopping behavior in ChefFlow longer
6. **Public proof profile** = reduces social/review validation exits
7. **Event logistics packet** = bridges venue, access, parking, weather, and maps
8. **Split-pay and contribution links** = reduces Venmo/Splitwise round-trips
9. **Post-event recap + share kit** = bridges photos, reviews, referrals, and memory
10. **Client memory archive** = eliminates "what did we have last time?" searching
