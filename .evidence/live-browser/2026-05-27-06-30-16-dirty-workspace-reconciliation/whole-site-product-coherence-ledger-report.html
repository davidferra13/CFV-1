Whole-Site Product Coherence Ledger

Queue-ready spec for a read-only ChefFlow audit system that generates JSON machine state and local HTML evidence reports for every major product surface.

Purpose

The ledger should answer whether ChefFlow's routes, navigation, role policies, domain promises, actions, data flows, runtime proof, and queue implications describe one coherent product. It should make missing or contradictory surfaces visible without implementing new product behavior.

Core Outputs

Artifact Suggested Path Contents
Machine state reports/product-coherence/state.json Route inventory, role policy, nav coverage, domain matrix, probes, evidence, queue mapping, findings, scores.
HTML index reports/product-coherence/index.html Executive scorecard, domain summaries, severity filters, screenshots, source links, queue links.
Per-route reports reports/product-coherence/routes/*.html Route contract, inbound paths, actions, data dependencies, runtime status, proof caveats.

Required Domains

Page X-Ray, Dinner Circles, Universal Rail Intelligence, Priority Queue, Commitment UI, Menu Intelligence, PIE, Client Intelligence, communications, lifecycle, ledger, navigation, Remy, automation, and CIL.

First Slice

Build only the read-only generator and report shell. Inputs should be route inventory, route policy, nav config, wiring audit results, affected-route probes, and a bounded browser evidence sample. No queue item should be created without explicit user approval.

Acceptance Gate

  • JSON validates and can be diffed between runs.
  • HTML opens offline and links to local screenshots and source evidence.
  • Protected routes treat auth redirects, 401, and 403 as reachable but not fully proven.
  • Findings are classified as keep, blocked, queue-candidate, rejected-expansion, or needs-user-approval.
  • No secrets, cookies, tokens, PII, or private client details are included.
